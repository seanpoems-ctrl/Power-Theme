# Thematic Scanner — CLAUDE.md

## Project Overview

**Thematic Scanner** is a stock market analysis platform that identifies bullish thematic trends in the US equity market. It has two main scanners:

1. **Thematic Scanner** — Daily end-of-day scrape: hierarchical theme → sub-theme → stock screening via Finviz
2. **Pre-Market Gapper Scanner** — Morning pre-market gap-up analysis with AI catalyst detection (Gemini)

Deployed on **GitHub Pages** as a static React app. Data is fetched nightly via GitHub Actions, saved to `public/*.json`, and served with the built app.

## Feature Reference

### Thematic Scanner (`scraper.py`)

**Data Pipeline:**
1. Discover all themes + sub-themes from Finviz screener dropdowns
2. Score all themes with composite: `0.2×1W + 0.3×1M + 0.3×3M + 0.2×6M` → select top 5
3. For each top theme, score + select top 5 sub-themes
4. For each sub-theme, fetch top 10 stocks with full detail
5. Enrich each stock: Finviz quote page (SMA20/50/200, ATR, ADR%) + yfinance (sparkline, earnings)
6. Build S&P 500 RS universe → calculate RS percentile (1–99 scale) per stock
7. Fetch SPY/QQQ market indicators → compute market signal
8. Output to `public/thematic_data.json`

**Key Functions:**
- `is_trading_day()` — NYSE calendar check via exchange_calendars
- `discover_themes()` — scrapes Finviz theme/sub-theme dropdowns
- `fetch_screener_stocks()` — paginated Finviz screener (max 10 pages × 20 stocks)
- `fetch_stock_detail()` — parses Finviz quote page for price, SMA ratios, ATR, ADR%, 52W high
- `fetch_sparkline()` — 6-month daily closes via yfinance
- `fetch_earnings_yf()` — next earnings date via yfinance
- `fetch_market_indicators()` — SPY/QQQ SMA50/SMA200/EMA10/EMA20 metrics
- `_build_sp500_rs_universe()` — S&P 500 list from Wikipedia + batch yfinance download
- `_composite()` — theme/sub-theme/stock scoring formula
- `_market_signal()` — returns `"green"` / `"yellow"` / `"red"`

**Retry logic:** 4 attempts, 180s between retries. Shorter sleeps in CI (`CI` env var detected).

### Pre-Market Gapper Scanner (`gapper_service.py`)

**Data Pipeline:**
1. Query TradingView screener: gap ≥5%, PM volume ≥200K, mkt cap ≥$2B, avg vol ≥500K, price $5–$200
2. Take top 20 gappers by pre-market % change
3. For each: fetch 24h Google News RSS headlines
4. Send to Gemini 2.5 Flash → classify catalyst + conviction score (25–99) + trade hypothesis
5. Output to `public/gapper_data.json`

**Catalyst Categories (9):**
- Earnings, Upgrade, FDA, Thematic Narratives, Government Policy, New Contract/Partnership, Institutional Buying, Insider Buying, Others

**Conviction-based strategies:**
- Earnings/Contract → "Gap & Go" (5-min ORB above PM high)
- Thematic/Government → "RS Hold" (dip-buy 9-EMA/VWAP)
- Upgrade → "Fade Candidate" (gap-fill risk)
- FDA → "Volatility Trap" (mean reversion)

### Frontend (`src/App.js`)

**Tab 1: Thematic Scanner**
- **MarketCondition** — Green/Yellow/Red signal with SPY/QQQ SMA metrics and trading guidance
- **Leaderboard** — Top 5 themes ranked by perf (switchable 1D/1W/1M/3M/6M)
- **CorrelationGuard** — Pearson correlation warning when top 3 themes correlation >0.80
- **CounterTrendWarning** — Dead-cat bounce alert when #1 momentum theme is down >15% over 6M
- **EliteBadges** — Triple Crown, Volatility King, Liquidity Monster, VCP Tightening
- **GradeClassification** — A+ (RS≥90 + above all SMAs), A (RS≥80 + above SMA50/200), B (above SMA200)
- **TechnicalFlags** — VCP Stage 1, VDU (volume dry-up), Tight (3-day range <1.5%), ID (inside day)
- **StockTable** — Sortable, filterable table with 52W High, dist%, RVOL, avg $ vol, ADR%, RS score, vs SPY, performance cells (1D–6M), earnings date, sparkline
- **Filters** — Min $ vol, min ADR%, min RS, max dist to 52W high
- **Collapsible hierarchy** — Theme → Sub-theme → Stock table

**Tab 2: Pre-Market Gappers**
- GapperTable with catalyst badge, Gemini reasoning, trade hypothesis, conviction bar

**SVG Sparkline** — lightweight 6-month price mini-chart with gradient fill

## Pure Play Detection

A stock is `pure_play: true` if it appears in **only one** sub-theme across the entire dataset. This is calculated post-collection by counting sub-theme appearances per ticker.

## Relative Strength (RS) Scoring

- Universe: S&P 1500 (S&P 500 + MidCap 400 + SmallCap 600, lists scraped from Wikipedia) **plus the scanned thematic stocks themselves** — broadened so high-ADR mid-caps aren't percentile-ranked against mega-caps only
- Metric: 6-month total return
- Output: Percentile rank 1–99 (99 = top performer)
- Fallbacks: S&P 500-only if the mid/small extension fails (`_extend_rs_universe_midsmall`); internal ranking within dataset if everything fails

## Theme Rotation / Acceleration Rank

`_add_rotation_ranks()` annotates `theme_rankings`, `finviz_theme_rankings`, and `industry_rankings` with:

- `rank_1w` / `rank_3m` — position when ranked by that window's perf (1 = best)
- `rotation_delta` — `rank_3m − rank_1w`; positive = short-term rank jumped ahead of long-term rank (early rotation in)
- `accelerating` — `true` when delta ≥ 25% of universe size (min 3) and 1W perf > 0

Was surfaced in the Scanner Leaderboard's sortable **ROT** column (⚡ badge = accelerating); that component was removed 2026-10-13. **ROT now lives in Themes → Theme Leaders** (`buildRotation` in `App.js`, computed client-side over the ~64 `leadership_theme` groups from each group's median 1W vs 3M return, same formula/threshold; window-independent so every table shows the same value; sortable ROT column in `ThemeTopTable`, hidden for the Sectors tables). The scraper's `rotation_delta` fields for the Finviz themes are computed but no longer displayed.

## Market Condition Signal (2026-09-22: reverted to cash ETFs)

`market_condition.spy` / `.qqq` / `.iwm` (top banner, Market Pulse card) are built from the **actual SPY/QQQ/IWM cash ETFs** — `fetch_market_indicators()` calls `_fetch_market_indicators_yfinance()` directly on the ETF ticker, and `_market_signal()` derives green/yellow/orange/red from price vs. EMA9/21/50/200. The header ticker tape shows separate real **SPX/NDX/DJI** cash-index fields (`market_condition.spx/.ndx/.dji`, via `fetch_cash_indices()` — `^GSPC`/`^NDX`/`^DJI`).

**History — why this was futures, then reverted:** a 2026-09-15 fix switched `spy`/`qqq`/`iwm` to continuous futures (`ES=F`/`NQ=F`/`RTY=F`) so the signal would be pre/post-market-aware instead of freezing at the 4PM cash close. The `_last_completed_session()` guard was added to pin the read to a "finalized" daily bar, since futures trade near-24h and Yahoo starts printing the next session's row as soon as evening trading resumes.

That guard turned out to be broken for futures: it only checked `now_et.hour >= 16` (a cash-market cutoff) before trusting a bar as final, but a continuous future's daily bar keeps getting revised by Yahoo for the *entire* ET calendar day, not just until 4PM — so "finalized" numbers silently drifted run to run (confirmed 2026-09-22: QQQ's supposedly-locked 09-21 bar read 30870.25 at 10:42pm ET, then 30784.75 after midnight, a ~0.3% swing). Since there's no reliable same-evening finality signal for this data source, the fix was reverted back to cash ETFs, whose daily bar genuinely is final at the 4PM close — exactly what `_last_completed_session()` was built to detect, just misapplied to the wrong instrument. Trade-off: the signal is back to reflecting the actual close rather than a live evening snapshot, same as before the Sept 15 fix. `_TV_INDEX_SYMBOL` (TradingView fallback, used only if yfinance is unavailable) was updated to match — `AMEX:SPY` / `NASDAQ:QQQ` / `AMEX:IWM` instead of the futures contracts.

## Inverse Arsenal (Short tab)

`inverse_arsenal_builder.py` (nightly step in `daily-scrape-deploy.yml`, after `etf_rs_builder.py`) writes `public/inverse_arsenal.json`, rendered by `InverseArsenalSection` under Clean Bases — Sell Watch.

Floors: avg volume ≥2M (Jeff Sun's Finviz inverse-ETF screen) and ≥$20M/day. Pinned names (`PINNED`: SQQQ SOXS LABD TZA UVIX ETHD) are kept but flagged ⚠ LIQ if they miss a floor. HOT = weekly volatility >3%.
- **Hot** — other 2x/3x inverses (mostly single-stock) passing the same rules.
- Universe comes from TradingView (`leveraged_flag == 'Inverse'`); Finviz's free tier ignores its ETF-type filters. TradingView does not flag the Bitcoin/Ether short funds as inverse, so `CRYPTO_INVERSE` fetches them by name. Perf is price-only 1D/1W/1M, same conventions as `etf_rs_builder.py`.

## COT tab (CFTC Commitment of Traders)

`cot_builder.py` (nightly step in `daily-scrape-deploy.yml`, after `inverse_arsenal_builder.py`) writes `public/cot_data.json` from the CFTC Public Reporting API. ~24 markets (`MARKETS` list: indices, crypto, metals, energy, bonds ZT/ZN/UB — ags/softs/livestock were dropped on request; re-add rows there to restore). CFTC has no 20Y contract, so bonds are 2Y/10Y plus Ultra Bond (UB) as the 30Y. ~5 years of weekly rows `[date, oi, s1_long, s1_short, s2_long, s2_short, s3_long, s3_short]`; each market carries `report`. The CFTC publishes Fridays 15:30 ET (Tuesday positions); the builder rewrites the file only when data changed, so nightly runs make no commit noise, and it refuses to publish if either report is missing. The workflow needs `git add -f public/cot_data.json` (new file; `add -u` skips untracked).

- **Two reports.** Everything except Treasuries uses **Legacy futures-only** (`6dca-aqww`): slots = Large Specs / Commercials / Small Specs. **Treasuries use TFF futures-only** (`gpe5-46if`): slots = Asset Managers / Leveraged Funds / Dealers (`TFF_GROUPS` in the builder). Reason: Legacy lumps hedged cash-futures basis trades into "Large Specs", so a Treasury Legacy index says nothing about direction. In TFF, **Asset Managers = real-money directional duration** (drives CROWDED LONG/SHORT for bonds), **Leveraged Funds = mostly basis-trade shorts** (gets a neutral blue `LEV FUNDS SHORT NEAR 3Y SMALLEST/LARGEST` label — smallest = trade being cut back, largest = big trade with unwind risk), Dealers = counterparty.
- **Frontend**: `src/CotTab.js` (tab "COT": grouped-bar net-positioning chart in SVG, searchable market picker, 3Y/1Y range-band toggles, per-group stat cards, two crowding scanners — Legacy markets, and a separate Treasuries/TFF one), `src/cotUtils.js` (pure helpers + `buildCotBrief`; `groupsFor(market)` returns the right group names/colours; tested in `cotUtils.test.js`), `src/cotBrief.js` (loader + strip for the brief). The three slot keys in code stay `ls`/`c`/`ss` for both reports.
- **COT index** = where current net sits between its low (0) and high (100) over the trailing 3Y (or 1Y). **Crowded** = primary-group (Large Specs, or Asset Managers for Treasuries) 3Y index ≥90 (long) / ≤10 (short). Contracts with <3Y history (SOL, XRP) use what exists and show `*`.
- **Market Situation brief** (`MarketSituationBlock`, Market Breadth tab): the Gemini prompt gets a `CFTC COT positioning` section plus a final "Futures Positioning / COT" paragraph (always last, so the existing paragraph numbers are unchanged), and a COT strip renders under the narrative. Cache key bumped to `gemini_market_situation_v7` (then `_v8` on 2026-10-07 for the breadth-cycle / divergence read). If `cot_data.json` is missing the brief just omits COT. The prompt spells out the Treasury semantics (asset managers = direction, leveraged-fund shorts = basis trade; the payload wording for basis extremes is explicit because the model inverted "smallest/largest" when left to infer it).
- The chart's tooltip "range" lines are true min→max of the primary group's net over the trailing 3Y / 1Y.

## Main stock universe (`screener_builder.py`)

`public/screener_stocks.json` = TradingView screener (NASDAQ/NYSE, `stock`+`dr`, mkt cap >$1B, 10d avg vol >500K shares, price >$5). TradingView can only sort server-side by *share* volume, which used to drop expensive liquid names (LLY, ASML, CAT, GS...), so the builder pulls the whole candidate pool (`QUERY_POOL`=4000, ~1,900 pass today), ranks locally by price × avg volume and keeps the top `TOP_N`=500 by **dollar** volume (2026-10-07; the min is now ~$239M/day vs $24M before). Display order is still ADR% × Avg$Vol. A warning logs if the pool is ever full.

`extension` (the **Extension** column in the Stock Screener table every Focus List table, the Daily Stock Universe, and the Market Leaders/Laggards cards — `focus_list_scanner.py` and `universe_builder.py` (`fetch_extensions`) compute it the same way from TradingView `SMA50`/`ATR`) = Jeff Sun's ATR% multiple from the 50-MA: `((close / SMA50) − 1) / (ATR / close)`, from TradingView's `SMA50` + `ATR`. Colours: ≥4x amber (stretched), ≥7x red (overextended), negative = below the 50-MA. Stocks with a recent spin-off/split TradingView hasn't adjusted (e.g. CTVA) give a misleading value.

## Universe mode (Watchlist → 🌐 Universe)

`UniverseScreen` in `App.js` (mode key `adrUniverse`; mode `universe` is Group ETF). Reads `screener_stocks.json` and shows stocks with **ADR > 5% · Avg $ Vol > $500M · Avg Vol > 1M shares** (all editable, kept in localStorage `universe_criteria_v1`). `UNIVERSE_EXCLUDE` drops tickers with known-bad data (CTVA).

## Leadership ladder (Watchlist → 🏆 Leadership)

Modelled on the Liquid Leadership / NEL layout (i-manage-risk.github.io/NEL): a snapshot, then **LL → NEL → T-NEL** per window (1M/3M/6M/1Y). `leadership_builder.py` (nightly, after `leveraged_etf_builder.py`) writes `public/leadership.json` + `public/leadership_history.json` (daily industry counts, 60 days — the snapshot sparklines need ≥2 days). `LeadershipScreen` in `App.js` applies the tiers client-side so the thresholds are editable (localStorage `leadership_criteria_v1`).

- **LL** — top 20 by 1M/3M/6M/1Y performance among NASDAQ/NYSE/AMEX stocks+ADRs, price ≥ $2, avg vol ≥ 500K, avg $ vol (10d) ≥ $40M. **NEL** — LL with Extension < 4× (default). **T-NEL** — NEL with RMV ≤ 20 (default) and optional Coil ≥ N.
- **RMV and Coil are our own definitions** (his formulas aren't published): RMV = 5-day avg true range ÷ close, scaled 0–100 between its own min/max over the last 50 sessions; Coil = consecutive sessions (max 10) with true range below the 20-day average. Computed from Yahoo bars for the LL tickers only. Copy = comma-separated tickers (TradingView-importable); Export = CSV.
- **Super Liquid tier** (Stocks → Super Liquid, `LeadershipStocksView pool="super"`; added 2026-10-08 from the reference page's `super-liquid.html`): the same ladder SLL → S-NEL → T-SNEL on the top **10** per window among stocks with avg $ vol ≥ **$1B** (`SUPER_MIN_DOLLAR_VOLUME`, `SUPER_TOP_N` in the builder; ~109 stocks). `leadership.json` gains `super_leaders`, `super_industry_counts`, `super_top_n`, `super_pool_size`; `leadership_history.json` rows gain a `super` key (sparklines skip days without it). **The reference page doesn't publish its cut-off or universe** — $1B reproduces most of his list (CIEN/CRDO/ALAB/HPE in; OKTA/TEAM/AXTI/SMTC out) but we also surface a few names he doesn't (PTC, MRNA, CRWD, PANW, SNOW, ACN, VLO), so expect small differences. Every LL/SLL row also carries `lev_etf` = the most liquid *long* leveraged ETF on the stock (shown as `AMD / AMDL`, from `leveraged_stock_etfs.json`); `leveraged_etf_builder.py`'s write floors were lowered to $5M/day and 100K shares (the Universe page applies its own floors in the browser) so smaller single-stock ETFs (NOWL, CRMG, LABX…) resolve. Extension / RMV / Coil cut-offs are shared with the liquid tier (same localStorage key).

## Pullback Watchlist (Stocks → Pullback Watchlist) — Martin Luk's pullback-buy method

Added 2026-10-12 from @OtherSideBJ's tweet (status 2109475443929972794) on Martin Luk (2025 US Investing Championship stock division, +969.8 %): wait for a strong stock's up-leg → it returns to daily support → buy when it turns back up (daily chart finds support, **minute chart gives the trigger**) → hold the stop, scale out into strength. `pullback_builder.py` (nightly, after `earnings_history_builder.py`; new file → `git add -f public/pullback_watchlist.json`) takes every ticker on **Focus List** (any scan), **Universe** (ADR > 5 %, $ vol > $500M, vol > 1M — the Universe-page defaults; CTVA excluded), **Liquid Leaders** and **Super Liquid Leaders** (any window), downloads 1y of daily bars from Yahoo in one batch and measures: up-leg % (swing low → swing high over the last 60 sessions), pullback % below that high, EMA10/EMA21/SMA50 distance in ATRs (`support` = whichever of EMA21 / SMA50 is nearest), above SMA50/200, turn-up day (green close above the prior high) / EMA10 reclaim / inside day / tight 3-day range / pullback volume vs the 50-day, a planning stop (lowest low of the last 5 sessions), risk % and risk ÷ ADR. `PullbackScreen` (`App.js`, mode `pullback`) loads the JSON and applies **editable** cut-offs (localStorage `pullback_criteria_v1`; defaults ADR ≥ 4, up-leg ≥ 25 %, pullback 4–30 %, support −1…+1.5 ATR, $ vol ≥ $20M, above the 50-day), list chips (F/U/L/S), an All/Trigger/Watch filter, a ranking score (`pullbackScore`: closeness to support, leg size, daily trigger, coiling, quiet volume, on several lists, stop within one ADR), Copy / Export / Mini Charts. **Table layout (2026-10-12):** `table-fixed` with `<colgroup>` percentage widths inside an `overflow-hidden` card, so it never scrolls horizontally; related numbers share two-line cells (Symbol + list badges, Up-leg/Pullback side by side, To support = level + ATRs, Stop · Risk, 1M · 3M, Status + flags) and each cell is still sortable by its main value. The header's ▦ Mini Charts button is the chart view (no per-row chart column — removed on request). **Guide:** a **📖 Guide** button (and a link in the "How this maps…" panel) opens `PullbackGuide`, a modal with the idea, the 4 steps mapped to columns, a daily routine, a glossary of every column / tag (Trigger, Watch, EMA10↑, Inside, Tight, Dry, Up-leg, Pullback, To support, ATR, ADR, Stop · Risk, Risk÷ADR, Ext., score recipe …), the filter bar and limits — keep it in sync when columns or rules change. **Limits:** Status "Trigger" is only a DAILY proxy — the real entry trigger (opening-range break, VWAP reclaim…) can't be computed from daily data and is still taken on the intraday chart; the rules are our reading of the tweet's image, not a published formula; leveraged-ETF-only Universe members are not included.

## Breadth Cycle (Breadth → Breadth Cycle)

`BreadthCycleTab` — a "time machine" breadth page modelled on the reference page's Breadth tab, built **only from `public/breadth_monitor.json`** (the Stockbee sheet: ±4% movers, 5/10-day ratios, quarter/month/34-day counts, T2108, S&P close; ~200 sessions from 2025-12-18). Time Machine = ‹ date ▾ › (any session; every panel and chart recomputes up to that date). Panels: cycle gauge (Expansion / Distribution / Contraction / Repair + Strength 0–100 + 5-session change), "Read on <date>" (Up/Down 4%, 5D/10D ratio cards, Quarter/Month ±25%/Month ±50%/34D ±13% counts), beginner's guide, historical charts (7 measures × 1W/1M/3M/6M/YTD/1Y, with an S&P close chart on the same window), and a sortable readings table (click a row to jump the time machine).

**Strength and phase are our own scoring** (the reference page doesn't publish its formula): Strength = equal-weight mean of six 0–100 scores — daily up/(up+down) of ±4% movers; 5-day ratio; 10-day ratio (ratio 1 → 50, 2 → 100, 0.5 → 0); quarter ±25% up share; 34-day ±13% up share; T2108. Phase: Expansion = strength ≥ 55 and not falling; Distribution = (≥ 45 and falling) or (≥ 55 and falling); Repair = strength < 55 and up ≥ 5 pts over 5 sessions; else Contraction. **Shared scoring + where it surfaces:** the scoring/phase/divergence logic lives in `src/breadthCycle.js` (tested in `breadthCycle.test.js`; `loadBreadthCycle()` shares one fetch). `breadthDivergence(pulseSignal, cycle)` compares the Market Pulse trend signal (green/yellow/orange/red) with the breadth phase: green + Contraction/Repair → **Narrow**, green + Distribution → **Fading**, green + Expansion → Confirmed, yellow + weak → No support, red/orange + Repair or T2108 ≤ 20 → **Bounce watch**, red/orange + Contraction → Confirms weakness. `BreadthChip` (phase + strength + divergence pill; click → Breadth Cycle page) is shown in the Scanner's Market Pulse card (with the explanation line) and on the Watchlist modes' Market Pulse bar; `BreadthBriefStrip` sits under the Market Situation narrative, `BreadthNote` + a chip sit inside the Breadth tab's Market Pulse banner (whose stats line now wraps instead of overflowing into the Daily Brief card), and the Gemini payload carries `breadth_cycle` + `pulse_breadth_divergence` (paragraphs 2 and 3 are told to use them). **Scenario engine + long history (added 2026-10-07):** the page's "What Tended To Happen Next?" panel and the 3Y/5Y/10Y/Max ranges run on `public/breadth_long_history.json`, built by `breadth_history_builder.py` (nightly, after `breadth_monitor.py`; incremental — only the current year's tab is re-read once the file exists, `--full` rebuilds). **Source = the same Stockbee Market Monitor Google Sheet that `stockbee.blogspot.com/p/mm.html` embeds** (spreadsheet id in `breadth_monitor.py`, one tab per year — `breadth_monitor.py` itself only ever kept the current year's ~200 rows). Header-driven parser (column layouts changed by era; 2007/2008 tabs are horizontal and skipped, so **history starts 2009-01-07 and the 2008 crash is not covered**, which understates 1-year downside odds); 5/10-day ratios are recomputed as sum(up 4%)/sum(down 4%); T2108 exists only for ~3,500 days; S&P closes come from Yahoo `^GSPC` for every date. Stockbee revises recent days (e.g. 10/6 down-4% went 206 → 211), which the nightly rebuild picks up. `src/breadthScenario.js` (tested in `breadthScenario.test.js`, incl. a no-look-ahead test) does the analog study: 9 z-scored features (5 breadth, 4 S&P: 21d/63d return, distance from 200d average, 20d realized vol), closest 15% = "core", Gaussian weights, overlap down-weighting, only outcomes complete by the selected date; thresholds ±5/10/15/20% for 1M/3M/6M/1Y. `BreadthCycleTab` is `React.memo`'d — App re-renders every second (countdown) and this page is heavy.

## Live quote fallback (Finnhub → Finance Query)

All browser-side live prices go through `src/finnhubQuote.js` (`fetchFinnhubQuote(sym, { maxAgeMs })`, cached 60 s). If Finnhub has no answer — HTTP 429, any error, no `REACT_APP_FINNHUB_KEY`, or its all-zero reply for symbols it doesn't carry — the lookup falls back to **Finance Query** (`https://finance-query.com/v2/quotes?symbols=…&fields=…`; public Yahoo-backed API, MIT-licensed project, CORS-open, no key). Fallback lookups issued in the same tick are sent as one batched request (dots → dashes: `BRK.B` → `BRK-B`); after a 429 Finnhub is skipped for 30 s. Quotes are reshaped to Finnhub's `{c, pc, d, dp, h, l, o}` (plus `_source: "finance-query"`) so no caller changed. It is a third-party hobby service with no SLA and unspecified rate limits — keep it a *fallback*, never the primary. Tests: `src/finnhubQuote.test.js` (18). A fully automated VCP breakout trading bot that complements the Thematic Scanner. The scanner identifies what to watch; the bot executes trades automatically.

**Location:** `/Users/ryanchen/Documents/Trading_Bot_code/`

**Architecture (6 core modules):**

| Module | Purpose |
|--------|---------|
| 1. Market Filter | SPY/QQQ best-of-two traffic light + Top 3 Sector + Stage 2 screener → Top 5 watchlist |
| 2. VCP Recognition | Price contraction pattern detection + Pivot price calculation |
| 3. Entry Guard | Breakout validation (volume ≥1.5× 50-day avg) + fake-out filter (closes below pivot = no entry) |
| 4. Risk Management | 0.3% max loss per trade, shares = (equity×0.003) / (entry−stop), 33% max single position |
| 5. Exit Strategy | Hard stop = LOD−1%, partial profit at +20% in 3–5 days (sell 50%), trailing stop on 10-EMA |
| 6. Earnings Filter | Block entry within 14 days of earnings; force exit if <10% profit and earnings within 3 days |

**Market Signal Logic (SPY/QQQ — take the stronger):**
- 🟢 Green: price > 20MA > 50MA > 200MA, all slopes up → full buying allowed
- 🟡 Yellow: broke below 20MA or 50MA but 200MA still rising → only buy "跌市照妖鏡" stocks (above their own 20/50MA + RS at new high)
- 🔴 Red: 10MA crosses below 20MA (both falling) OR price below 200MA with flat/down slope → no new positions

**Broker:** IBKR TWS Paper Trading via `ib_insync`

**Notifications:** Telegram Bot (entry signal, exit alert, weekly report)

**Scheduler:**
- 16:30 ET daily → screening + watchlist save to `data/watchlist/YYYY-MM-DD.json`
- Every 5 min during market hours → breakout check + position management
- Friday 16:30 → weekly P&L report
